src/app/core/guards/role.guard.ts

roleActivateGuard
Type : unknown
Default value : (allowedRoles: readonly UserRole[]): CanActivateFn => { return async () => { const authService = inject(AuthService); const router = inject(Router); await authService.whenReady(); if (!authService.isAuthenticated()) { return router.createUrlTree(['/login']); } const role = authService.role(); if (role && allowedRoles.includes(role)) { return true; } return router.createUrlTree(['/forbidden']); }; }

Barrera de vista del RBAC: redirige con UrlTree a /login o /forbidden si el rol no es válido.
roleMatchGuard
Type : unknown
Default value : (allowedRoles: readonly UserRole[]): CanMatchFn => { return async (_route: Route, _segments: UrlSegment[]) => { const authService = inject(AuthService); const router = inject(Router); await authService.whenReady(); if (!authService.isAuthenticated()) { return router.createUrlTree(['/login']); } const role = authService.role(); if (role && allowedRoles.includes(role)) { return true; } return router.createUrlTree(['/forbidden']); }; }

Factorías de autorización por rol (RBAC), siguiendo el patrón del Dossier_Guards:

  • roleMatchGuard (CanMatchFn): barrera de red; evita descargar el chunk lazy-loaded si el usuario no tiene el rol requerido.
  • roleActivateGuard (CanActivateFn): barrera de vista; evita instanciar el componente ya descargado si el rol no es válido. Ambas devuelven un UrlTree (nunca un booleano "a secas") para redirigir de forma atómica.
